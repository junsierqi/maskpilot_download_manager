# Task list interchange

Version 2 additionally accepts these optional, strictly typed public options:

- `mediaOrigins` is a bounded public string for standalone media or live recording tasks only. Each line is `0 https://cdn.example.com:443\n` for anonymous access or `1 https://cdn.example.com:443\n` when login material is required. At most 16 distinct exact HTTP(S) origins are accepted; paths, user information, wildcards and duplicates (including the primary origin) are rejected. Schema 19 preserves the same public representation. Credentials and approval are excluded; import, restart and URL changes require explicit review and new approval, plus missing login material, before any source contact. This does not extend browser/context grants.
- `httpMethod: "POST"` and `postContentType` describe an explicit single-attempt native HTTP(S) submission. Missing method means GET. The body and submission confirmation are excluded; imported POST tasks require newly supplied and confirmed content, including an explicitly empty body. No automatic replay or byte resume.
- `sftp` contains `authentication` (0 password, 1 private key), `hostKeySha256` (trusted SHA-256 Base64 fingerprint, optionally prefixed `SHA256:`), and `privateKeyFile` (explicit absolute local key path). SFTP source URLs require a valid pin. Username, password, key contents and key passphrase are excluded; reenter login before starting. Public-key mode never discovers ambient keys or agents.
- `live` contains mandatory `format` (0 HLS saved as MPEG-TS, 1 HTTP-FLV), `durationSeconds` (integer 1–172800), and `maxBytes` (integer 1048576–1099511627776). It selects standalone native live recording; destination must use `.ts` or `.flv` respectively. It cannot be combined with media selection, POST or non-HTTP sources. Import keeps public bounds and pauses the task; starting records the current feed rather than resuming old content.

These nested objects reject unknown keys and fractional/out-of-range values. They are unavailable in version 1. Live, SFTP and POST configuration never carries browser context authority, restored credentials or helper execution permission.

Project association (`projectId`, `projectRevision`) belongs to trusted task metadata in schema 13. It is not exported, imported or accepted in browser drafts. Plain request replay cannot claim a project child, and another project or revision cannot reuse its request binding. Import produces independent paused downloads; it does not reconstruct project manifests, publication receipts or ownership.

`responseUrl` and `responseContentType` are observed output from the current native HTTP attempt. They are never exported, imported or accepted as request authority; supplying them (including database-style snake_case names) is rejected. Schema 12 keeps unknown or ambiguous observed content types empty. Downloaded filenames do not establish a content type.

Desktop export writes UTF-8 JSON version 2: `{"version":2,"downloads":[...]}`. Input is limited to 32 MiB and 10,000 tasks. Unknown keys, wrong types, unsupported versions and invalid specifications fail before any task is added. Torrent metadata has its own 16 MiB per-item and 24 MiB aggregate decoded limits.

Each item contains `url`, `destination`, `category`, `connections`, credential-free `proxy`, mandatory boolean `proxyAuthenticationRequired` and `originAuthenticationRequired`, advisory `contextBound`, media options, expected SHA-256 and FTP TLS options. Torrent items additionally carry bounded metadata, file selection and seeding options. Cookies, authorization/custom headers, account/password values, credential references, owner IDs, session/grant tokens and helper executable paths are excluded. Original URLs and torrent metadata may contain signed parameters or private tracker credentials; protect exported files.

Version 1 remains readable, but did not record source authentication requirements. Preview explicitly reports this uncertainty. Review login requirements before resuming an old task list. A missing legacy proxy uses the visible local default; version 2 exports the explicit route, including an empty string for direct connections.

Version 2 optionally carries `mediaSelection`: `mode`, `primaryFormat`, `audioFormat` and `container`. Modes are automatic, muxed, separate video/audio, audio and video; the serialized values are validated bounded enums. Format IDs are bounded selector-free strings, never URLs. Missing selection preserves legacy automatic presets. Explicit choices require fresh source inspection before payload download; disappeared or incompatible formats fail without silently choosing another format. Selection carries no executable paths, authentication or route authority.

Version 2 also supports optional HTTP-only `maxStoredBytes` (integer 0–9007199254740991, zero means unrestricted) and boolean `sameOriginRedirectOnly`. Default values are omitted from export, preserving ordinary older lists. Import retains the constraints while creating paused tasks; wrong types, fractional/unsafe integers, non-HTTP policies and version 1 policy fields are rejected. Observed `responseUrl` is excluded and cannot be supplied by an imported list. These flags do not create source credentials or bypass queue policy.

Import validates the complete list and previews source, destination, route and authentication requirements. Nothing is added before confirmation. All imported tasks belong to the standalone area and default queue, with manual Paused intent. Queue membership and policy are not imported; move inactive tasks explicitly after import. `contextBound` is informational: it cannot restore a browser identity or grant authority. Local trusted configuration supplies media executable paths.

After confirmation, each task is persisted sequentially with a stable import request ID. If a save fails, accepted tasks remain, the remaining batch stays in memory and the next Import action offers to retry the remaining items. Cancel creates no additional tasks and retains a pending retry. The explicit Discard remaining action releases the pending batch so another file can be selected; already accepted tasks remain. Closing the application also discards the remaining in-memory batch. Import is not an atomic transaction spanning the entire batch.

Required authentication survives export, import and restart even though secret material does not. Resume fails before network/helper creation until credentials are refreshed, or a standalone user explicitly clears the source-login requirement. Profile tasks must instead use an owner-bound, exact-URL browser grant; they cannot be converted by editing task metadata.
